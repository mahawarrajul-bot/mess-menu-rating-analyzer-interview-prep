1. Two-minute pitch

Problem. A hostel mess manager gets complaints but no reliable evidence of which dishes students like, which are getting worse, or which weekday is weak. A raw star average is misleading: a dish with two 5★ ratings beats one with 200 ratings averaging 4.3.

Users. Students (rate a meal on their phone, installable PWA, reminder after lunch/dinner) and the mess manager (uploads the weekly menu, reads the dashboard and comments).

What stands out.

  • Statistics are written by hand in pure-stdlib Python: Bayesian average with interval, trend test with Benjamini–Hochberg correction, weekday ANOVA, rule-based Keep / Drop / Watch / Need-more-data with a reason string.
  • A seeded simulator plants known patterns and a recovery check proves the analysis finds them.
  • Pseudonymous ratings: a rating row holds no student id, roll or email; reminders still skip students who already rated (HMAC token).
  • Menus are versioned and append-only; each served meal is a frozen snapshot, so ratings always refer to what was served.

Proof (simulated data, seed 42, 7,705 ratings, from demo_report.json). All 6 recovery checks pass: Paneer Special (2×5★, raw rank 1) drops to Bayesian rank 6 with "need more data"; Dal Fry is flagged declining (−0.98 stars per 28 days); Wednesday found as the weak weekday (F = 28.0); Veg Biryani is "need more data" (80 ratings, 2 serving days); Lauki Sabzi (raw 2.05) is Drop with top tags oily/bland. Per docs/progress.md, recovery passes for 30 seeds; the weekday-adjusted trend finds the decline 60/60 seeds versus 45/60 without adjustment.

2. Architecture and request flow

Flow: a rating

  1. Student signs in via emailed single-use link → signed cookie.
  2. /api/me/meals lists open meals; form shows that meal's frozen dish snapshot.
  3. POST /api/meals/[id]/rate validates input (zod), computes rater_token = HMAC(PEPPER, student_id : meal_service_id), inserts submission + dish ratings in one transaction; a UNIQUE constraint blocks a second rating.

Flow: dashboard

  1. /api/stats serves a cached snapshot (15 min). If stale, Next.js queries ratings grouped by (dish, date, stars, tags) with counts, POSTs them to the Python function, stores the report; on failure serves the old snapshot marked stale.
  2. Python never reads the DB (design change recorded in specs/design.md, T26).

4. Tech-stack decisions and why

ChoiceWhy
Next.js (App Router) + TypeScript + TailwindOne codebase for UI and API; free Vercel hosting; types catch errors.
Postgres + plain SQL migrationsReal constraints (UNIQUE, CHECK, append-only triggers) enforce rules in the database; simple runner is easy to explain.
Pure-stdlib Python for statisticsSpec A11: this machine's app-control policy blocks numpy.random/scipy.stats DLLs; dependency-free is small and explainable. scipy only in optional test cross-checks.
Python separate from DBPure functions on lists are testable with no DB; no DB credentials in the Python runtime; no personal fields reach it.
Bayesian shrinkage, not a minimum-vote cutoffSmooth, gives an interval. Trade-off: normal approximation for 1–5 data.
PWA + web push + email fallbackNo app-store install; email covers iPhone/no-push cases. Resend free tier ≈ 100 emails/day (capped at 80 per run in config).
Two daily Vercel crons + GitHub Actions backupHobby plan allows 2 once-a-day crons firing anywhere in the hour; jobs check "has the meal ended" and are idempotent.
Thresholds in config/stats.jsonNo magic numbers; sensitivity can be shown by editing one file.

Weekday: Wednesday found weakest (F = 28.0, p = 3.1e-33). Recovery passes on 30 seeds; adjusted trend finds the decline on 60/60 seeds versus 45/60 unadjusted.

What the results do NOT show

  • Not real-world accuracy. The simulator and the analysis share my assumptions, so recovery proves the code finds what I planted, not that real students behave this way.
  • Weekday effect size is understated: estimated ≈ −0.27 vs planted −0.45 (dishes served on only one weekday absorb the effect). η² is only about 2%: significant but small.
  • No real students, no usability test, no load test, no evaluation of whether managers act on the output.
  • The p-value of 3.1e-33 reflects thousands of simulated ratings, not practical importance.

8. Limitations, trade-offs, next steps

  • Pseudonymous, not anonymous: the server holds PEPPER and can recompute tokens to know whether a student rated (needed for reminders). Changing PEPPER orphans students.
  • Normal approximation for discrete 1–5 ratings; same σ for all dishes; C = 10 is a choice. Alternative: Dirichlet–multinomial.
  • Weekday offsets are partial (conservative) so a confounded dish keeps some noise.
  • Free-tier limits: ~100 emails/day, 2 crons; iPhone push only after Add to Home Screen.
  • Demo data are simulated; demo and live scopes are kept separate.
  • Dark mode follows the OS only (no manual toggle in the app).
  • Next steps: pilot with a real hostel block; usability-time the 20-second claim; add a CI test workflow; compare Bayesian model with Dirichlet–multinomial; real-data sensitivity analysis for C.

10. Glossary

TermMeaning
Bayesian averageMean pulled toward the global mean by C imaginary ratings; stabilises dishes with few votes.
Credible/95% intervalRange likely to contain the dish's true mean under the model.
OLSOrdinary least squares line fit; slope = stars per day.
p-valueChance of a result at least this extreme if there were no real effect; not the probability the effect is real.
Benjamini–HochbergControls the false-discovery rate when testing many dishes.
ANOVA / F / η²Tests whether group means differ; F = between/within variation; η² = share of variation explained.
ResidualRating minus the dish's own score (removes dish effect).
Effect size gateMinimum practical change (0.3 stars/28 days) in addition to p < 0.05.
HMAC / PEPPERKeyed hash; PEPPER is the server secret key.
PseudonymisationReplacing identity with a token; reversible by whoever holds the key.
Append-onlyRows are never updated/deleted (enforced by DB triggers).
PWA / VAPIDInstallable web app / key pair identifying the push sender.
Small-cell suppressionHiding counts below 5 so few raters cannot be singled out.
ISTAsia/Kolkata, UTC+05:30, no DST.
